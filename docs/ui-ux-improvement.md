# UI/UX 개선 기획 — 호호가족의 체스게임

> **이 문서의 역할**: 디자인 개선 방향과 우선순위를 정리하는 살아있는 기획서다.  
> 레퍼런스 분석 → 개선 방향 → 우선순위 순으로 구성되어 있으며, 최종 방향이 결정되면 `spec.md`와 `requirements.md`에 반영한다.

---

## 1. 현황 분석

### 1-1. 홈 화면

현재 홈 화면은 세로 스크롤 레이아웃으로 섹션이 순차적으로 쌓여 있다.

| 구성 요소 | 현황 | 문제점 |
|-----------|------|--------|
| 헤더 | 아이콘 + 텍스트 타이틀 | 시각적 임팩트 없음, 게임 분위기 전달 안 됨 |
| 규칙 카드 그리드 | 텍스트 + 설명만 있는 6개 카드 | 각 규칙의 특성이 시각적으로 구분되지 않음 |
| 상대 선택 | 2인 대전 / AI 대전 두 버튼 | 선택된 상태와 아닌 상태 구분이 약함 |
| 시간 선택 | 5개 pill 버튼 | 기능적이나 게임다운 느낌 없음 |
| 플레이어 이름 입력 | 흰 배경 텍스트 필드 | 맥락 없이 배치, 설명 부족 |
| 시작 버튼 | 갈색 전체폭 버튼 | 적절하나 위에 시각적 흥미 요소 없음 |

### 1-2. 인게임 화면

| 구성 요소 | 현황 | 문제점 |
|-----------|------|--------|
| 플레이어 패널 (상/하) | 컬러 도트 + 이름 텍스트만 | 현재 턴 표시 약함, 타이머·잡은 기물 정보 없음 |
| 체스 보드 | 중앙 배치, 좌표 표시 | 자체적으로 잘 구성됨 |
| 사이드 패널 | 기보 + 되돌리기/힌트/항복 + FEN 박스 | 게임 도구(기보, 컨트롤)와 기술 정보(FEN)가 혼재 |
| 홈으로 버튼 | 왼쪽 상단 텍스트 버튼 | 게임 중 실수로 누를 위험, 확인 없음 |
| 효과음 토글 | 우측 상단 | 위치 적절 |

### 1-3. 게임 종료 화면

현재 게임 종료 시 다이얼로그(모달) 형태로 결과가 표시된다. 별도 전체 화면 없이 보드 위에 오버레이만 존재한다. 승리/패배의 감정적 피드백이 약하다. → **전체 화면으로 전환하기로 결정.**

## 2. 레퍼런스 분석 — Duolingo Chess (Mobbin iOS)

Mobbin에서 수집한 가장 관련성 높은 레퍼런스는 Duolingo의 Chess 기능 화면들이다.

### 2-1. 체스 로비 화면 (Play Chess)

```
┌─────────────────────────────┐
│                             │
│    [캐릭터 + 체스보드 일러스트]    │
│                             │
│         Play Chess          │
│  Play real, timed matches   │
│                             │
│  ┌──────┐ ┌──────┐ ┌─────┐  │
│  │MATCH │ │ WINS │ │ ELO │  │
│  │  125 │ │  59  │ │1049 │  │
│  └──────┘ └──────┘ └─────┘  │
│                             │
│  [ PLAY A PERSON  +50 XP ]  │
│  [   PLAY OSCAR   +50 XP ]  │
│                             │
└─────────────────────────────┘
```

**핵심 패턴:**
- 캐릭터/일러스트로 게임 분위기를 즉각 전달
- 통계(매치/승리/ELO)를 색상 구분된 3개 카드로 가로 배열
- CTA 버튼에 보상(+XP) 표시로 플레이 동기 부여
- 단순한 2개 버튼으로 진입 경로 명확화

### 2-2. 승리 화면 (Match Complete!)

```
┌─────────────────────────────┐
│                             │
│   [캐릭터 금메달 들고 환호]       │
│        ✦  ✦  ✦              │
│                             │
│      Match complete!        │
│   You won! Victory is sweet!│
│                             │
│  ┌──────┐ ┌──────┐ ┌─────┐  │
│  │TOTAL │ │MATCH │ │ ELO │  │
│  │XP 50 │ │  1   │ │ 276 │  │
│  └──────┘ └──────┘ └─────┘  │
│                             │
│  [         CLAIM XP        ]│
└─────────────────────────────┘
```

**핵심 패턴:**
- 흰 배경 + 파란 스파클 → 기쁨, 경쾌함 강조
- 캐릭터 일러스트로 즉각적 감정 전달
- 게임 결과를 통계 카드 3개로 요약
- 단일 행동(CLAIM XP) → 다음 화면으로 명확한 흐름

### 2-3. 패배 화면 (Sad Face.)

```
┌─────────────────────────────┐
│ ┌────────────────────────┐  │
│ │ [패배자 캐릭터] [승자 캐릭터]│  │ ← 분홍 배경 블록
│ └────────────────────────┘  │
│                             │
│          Sad face.          │
│  Losing makes me cry on     │
│  the outside AND inside!    │
│                             │
│  ┌──────┐ ┌──────┐ ┌─────┐  │
│  │TOTAL │ │MATCH │ │ ELO │  │
│  │XP 30 │ │ 126  │ │1049 │  │
│  └──────┘ └──────┘ └─────┘  │
│                             │
│  [        CONTINUE         ]│
└─────────────────────────────┘
```

**핵심 패턴:**
- 승자와 패자 캐릭터를 나란히 배치 → 결과를 서사적으로 전달
- 분홍 배경 블록 → 패배 감정 색상 코딩
- 공감하는 문구로 사용자 이탈 방지
- 승리 화면과 동일한 통계 카드 → 일관된 UX 패턴

### 2-4. 레퍼런스 요약

| 요소 | Duolingo 패턴 | 적용 포인트 |
|------|--------------|-------------|
| 감정 표현 | 캐릭터 일러스트로 즉각 전달 | 게임 종료 화면에 감정 피드백 추가 |
| 통계 카드 | 색상 구분 + 아이콘 + 숫자 | 플레이어 패널 및 결과 화면 |
| CTA 버튼 | 전체폭, 단색, 명확한 라벨 | 현재와 유사, 보상 표시 추가 고려 |
| 배경 색상 | 결과에 따라 배경색 전환 | 승리/패배 화면 배경색 분기 |

## 3. 개선 방향

### 3-1. 전체 디자인 언어

현재의 따뜻한 베이지/갈색 팔레트는 유지한다. 여기에 아래 요소를 보강한다.

| 영역 | 현재 | 개선 방향 |
|------|------|----------|
| 색상 | 베이지 + 갈색 모노톤 | 턴/상태에 따른 포인트 컬러 추가 (활성 플레이어 강조) |
| 타이포그래피 | 시스템 폰트, 단일 웨이트 | 타이틀에 굵은 웨이트 강조, 계층 명확화 |
| 일러스트 | 없음 | 게임 종료 화면 등 일부 화면에 심플 일러스트 추가 (결정) |
| 애니메이션 | 기물 이동, 펄싱 | 상태 전환(턴 교체, 게임 종료) 시 화면 전환 모션 |
| 아이콘 | 혼재 (이모지 + 텍스트) | 일관된 아이콘 시스템 정립 |

### 3-2. 홈 화면

#### 현재 문제
긴 수직 스크롤로 인해 전체 구성이 한눈에 들어오지 않고, 게임 선택 과정이 체크리스트처럼 느껴진다.

#### 개선 방향

**A안 — 섹션 압축 + 시각적 강조**
- 헤더 아래 규칙 선택을 가장 넓게 배치 (변형 규칙이 핵심 차별점이므로)
- 상대/시간 선택을 2열 그리드로 묶어 공간 절약
- 각 규칙 카드에 아이콘/색상 추가 → 클릭 전에도 차이를 느낄 수 있도록

```
┌─────────────────────────────────────────┐
│         👑 호호가족의 체스게임             │
│       전략의 게임에 오신 것을 환영합니다     │
├─────────────────────────────────────────┤
│ 규칙                                     │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ │
│  │♟ 표준    │ │⚄ Chess960│ │🔄Crazy..│ │
│  │선택됨 ●  │ │          │ │          │ │
│  └──────────┘ └──────────┘ └──────────┘ │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ │
│  │🌫 Fog..  │ │💥Atomic  │ │👑 킹2개  │ │
│  └──────────┘ └──────────┘ └──────────┘ │
├─────────────────────────────────────────┤
│ 상대    [👥 2인 대전]  [🤖 AI 대전]       │
│ 시간    [3분][5분][10분][30분][∞]         │
├─────────────────────────────────────────┤
│ ⬜ 플레이어 1  [이름 입력...]              │
│ ⬛ 플레이어 2  [이름 입력...]              │
├─────────────────────────────────────────┤
│         [        게임 시작       ]        │
└─────────────────────────────────────────┘
```

**B안 — 단계별 선택 플로우 (Wizard)**
- 홈 화면을 하나의 긴 폼 대신 3단계 흐름으로 분리
  1. 규칙 선택 (카드 선택)
  2. 게임 설정 (상대/시간)
  3. 플레이어 이름
- 각 단계 상단에 진행 표시기(Progress bar) 노출
- 장점: 각 단계에 집중, 선택지가 명확
- 단점: 클릭 횟수 증가, 빠른 게임 시작이 어려움

**결정: A안** — 현재 수직 스크롤 구조를 유지하되 시각 계층을 개선한다. B안의 진행 표시기 개념은 선택 강조(active border)로 대체.

#### 규칙 카드 개선

| 규칙 | 제안 아이콘 | 제안 배경 컬러 |
|------|------------|--------------|
| 표준 | ♟ | 현재 갈색 유지 |
| Chess960 | 🎲 | 남색 계열 |
| Crazyhouse | 🔄 | 주황 계열 |
| Fog of War | 🌫️ | 회청색 계열 |
| Atomic | 💥 | 빨강/적색 계열 |
| 킹 2개 | 👑👑 | 금색 계열 |
| 아마존 | ⚡ | 보라 계열 |

### 3-3. 인게임 화면

#### 플레이어 패널

현재 플레이어 패널은 가장 개선 효과가 큰 부분이다.

**현재**: 컬러 도트 + 이름 텍스트 한 줄

**개선**: 정보 밀도를 높인 패널

```
┌─────────────────────────────────────────────┐
│ ⚫ 김철수              잡은 기물: ♙♙ +2     │
│                         ⏱ 04:32             │
└─────────────────────────────────────────────┘
```

- 플레이어 색상 도트 → 더 크고 명확한 아이콘 또는 배경색으로
- 잡은 기물 인라인 표시 (현재도 있으나 패널 외부에 배치)
- 타이머 패널 내부에 통합
- **활성 턴** 시: 패널 테두리 포인트 컬러 + 왼쪽 강조 바

```
현재 턴:
┌═══════════════════════════════════════════╗  ← 포인트 컬러 테두리
║ ⚪ 이영희              잡은 기물: ♟♟♟    ║
║                         ⏱ 07:15  ▶       ║
╚═══════════════════════════════════════════╝

대기 중:
┌─────────────────────────────────────────────┐
│ ⚫ 김철수              잡은 기물: ♙♙ +2     │
│                         ⏱ 04:32  ‖         │
└─────────────────────────────────────────────┘
```

#### 사이드 패널 구조 개선

현재 사이드 패널에 기보, 컨트롤 버튼, FEN이 혼재한다.

**개선: 역할 분리**

```
┌─────────────────────┐
│ 2인 대전   🔊 ✕     │ ← 모드 표시 + 사운드 토글
├─────────────────────┤
│ 기보                 │
│ 1. e4  e5            │
│ 2. Nf3 Nc6           │
│ (스크롤 가능 영역)    │
├─────────────────────┤
│ [↩ 되돌리기]         │
│ [💡 힌트 (3)]        │
│ [🏳 항복]            │
├─────────────────────┤
│ ⋯ 추가 옵션 ∨        │ ← FEN 등은 접힌 상태로
└─────────────────────┘
```

- FEN 섹션을 "추가 옵션"으로 기본 접힘 처리
- 기보 영역 상단에 현재 수 수(手) 표시
- 버튼 그룹을 시각적으로 묶음 (카드 배경 또는 분리선)

#### 홈으로 버튼

- 현재: 왼쪽 상단 "← 홈" 텍스트 버튼 (오조작 위험)
- 개선: 항복 버튼과 같은 사이드 패널 하단으로 이동하거나, 탭 시 "정말 나가시겠습니까?" 확인 다이얼로그 추가

### 3-4. 게임 종료 화면

현재 모달 다이얼로그 → **전체 화면 결과 화면**으로 전환

| 시간 초과 | 시간 초과 | 시간이 다 됐습니다 |

## 4. UI 컴포넌트 개선

### 4-1. 버튼 시스템

| 레벨 | 용도 | 스타일 |
|------|------|--------|
| Primary | 게임 시작, 주요 CTA | 현재 갈색 → 유지, 더 뚜렷한 호버 효과 추가 |
| Secondary | 되돌리기, 힌트 | 외곽선(outline) 스타일, 배경 없음 |
| Danger | 항복, 나가기 | 연한 빨강 텍스트/아이콘 |
| Ghost | 기타 보조 기능 | 텍스트만, 낮은 강조 |

현재: 버튼 스타일 혼재 (텍스트 버튼, 갈색 채운 버튼, 아웃라인 없는 버튼)  
개선: 위 4단계로 통일

### 4-2. 카드 컴포넌트

규칙 선택 카드, 통계 카드, 플레이어 패널 등에 사용되는 카드 스타일 통일.

```
기본 카드:
- border-radius: 12px
- border: 1px solid rgba(갈색, 0.2)
- background: 흰색 또는 크림
- padding: 16px
- box-shadow: 0 2px 8px rgba(0,0,0,0.06)

선택된 카드 (active):
- border: 2px solid [포인트 컬러]
- background: [포인트 컬러 10% 투명도]
```

### 4-3. 타이머 표시

| 상태 | 색상 | 크기 |
|------|------|------|
| 여유 (> 1분) | 기본 텍스트 색상 | 중간 |
| 주의 (30초~1분) | 주황색 | 중간 |
| 위험 (< 30초) | 빨간색 + 숫자 커짐 (pulse) | 크게 |
| 무제한 | "∞" 표시 | 작게 |

### 4-4. 폰트 사이즈 시스템

현재 10~64px까지 파편화된 고정 사이즈가 혼재해 있어 모바일에서 가독성이 낮다.

**현황 문제 목록**

| 크기 | 사용 위치 | 문제 |
|------|-----------|------|
| 10px | FEN 레이블·텍스트, 전적 날짜, 난이도 설명 | 모바일에서 사실상 읽기 불가 |
| 11px | 규칙 카드 설명, 보드 좌표(a–h/1–8), 기보 헤더·수 번호, 체크 뱃지 | iOS 최소 권장 미달 |
| 12px | 시간 선택 버튼, 기보 빈 상태 안내, 항복 확인 버튼 | 터치 타겟 텍스트로 너무 작음 |
| 13px | 규칙 카드 이름, 기보 이동 표기, 재료 우세 수치 | 보조 텍스트 경계선 |

**개선 방향 — 3단계 스케일로 통일**

| 역할 | 현재 | 목표 | 적용 대상 |
|------|------|------|-----------|
| 캡션 (보조 정보) | 10–11px | **12px** | 보드 좌표, 체크 뱃지, FEN 관련 |
| 보조 텍스트 | 11–13px | **13–14px** | 규칙 카드 설명, 기보 수 번호·헤더, 전적 날짜 |
| 본문 | 13–15px | **15–16px** | 규칙 카드 이름, 시간 선택 버튼, 기보 이동 표기 |
| 강조 | 16–18px | 유지 | 플레이어 이름, 섹션 라벨 |

> **참고**: iOS 접근성 권장 최소 본문 16px, 보조 텍스트 13px 이상.  
> FEN 텍스트(기술 정보)는 10px 유지 허용 — 단, 기본 접힘으로 처리 시 노출 빈도 낮음.

### 4-5. 색상 토큰 제안

현재 코드에 하드코딩된 색상을 CSS custom property로 정리.

```css
--color-board-light: #f0d9b5;  /* 보드 밝은 칸 */
--color-board-dark: #b58863;   /* 보드 어두운 칸 */
--color-bg: #f5f0eb;           /* 앱 배경 */
--color-surface: #ffffff;      /* 카드/패널 배경 */
--color-primary: #7c4f3a;      /* 주요 CTA 갈색 */
--color-active: #4a90d9;       /* 현재 턴 포인트 컬러 — 결정: 파란색 계열 */
--color-danger: #c0392b;       /* 위험/항복 */
--color-warning: #e67e22;      /* 타이머 경고 */
--color-success: #27ae60;      /* 승리/확인 */
--color-text-primary: #2c1810; /* 주 텍스트 */
--color-text-secondary: #7a6356; /* 보조 텍스트 */
```

## 5. 모바일 대응 (Phase 7 연계)

Phase 7에서 모바일 대응이 계획되어 있으므로, UI 개선 시 모바일 퍼스트 관점을 함께 고려한다.

| 화면 | 데스크톱 레이아웃 | 모바일 레이아웃 |
|------|----------------|---------------|
| 홈 | 현재 중앙 정렬 세로 스크롤 | 동일 (폭만 조정) |
| 인게임 | 보드 + 오른쪽 사이드 패널 | 보드 → 패널 세로 배치 |
| 게임 종료 | 중앙 카드 모달 → 전체 화면 | 전체 화면 |

모바일에서 플레이어 패널은 compact 모드로 한 줄로 압축:
```
[⚫] 김철수  ♙♙+2  |  04:32 ▶
```

## 6. 우선순위 및 구현 계획

### High (즉각 효과 큰 것)

1. **플레이어 패널 개선** — 타이머 통합, 활성 턴 포인트 컬러 테두리  
2. **게임 종료 화면 전환** — 전체 화면 + 결과 유형별 배경 분기  
3. **규칙 카드 아이콘 추가** — 각 규칙에 구분 아이콘/배경색  
4. **사이드 패널 FEN 접힘** — 기본 접힘 처리로 노이즈 감소  

### Medium (UX 완성도 향상)

5. **폰트 사이즈 통일** — 10–11px → 12px 캡션 / 13px → 14px 보조 / 본문 15–16px  
6. **홈 화면 헤더 일러스트** — 체스 캐릭터 또는 비주얼 요소 추가  
7. **버튼 시스템 정리** — Primary/Secondary/Danger/Ghost 통일  
8. **색상 토큰 CSS 변수화** — 하드코딩된 색상을 CSS custom property로  
9. **타이머 상태 색상 전환** — 주의/위험 구간에서 색상 변화  

### Low (polish)

9. **승리/패배 파티클 효과**  
10. **화면 전환 모션** (게임 시작/종료)
