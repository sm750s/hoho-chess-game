# 기획서 — 호호가족의 체스게임

> **이 문서의 역할**: 무엇을 만들 것인지 정의합니다. 기능의 범위, 우선순위, UX 요구사항을 기술합니다.
> 구현 방법·파일 경로·완료 여부는 `chess-game/docs/requirements.md`(구현 현황)에서 관리합니다.

## 목표

- 웹 브라우저에서 플레이 가능한 체스 게임 구현
- 표준 규칙을 기반으로, 변형 규칙을 교체하며 플레이할 수 있는 구조 제공

---

## 기술 스택

| 역할 | 선택 |
|------|------|
| UI 프레임워크 | React + TypeScript |
| 빌드 도구 | Vite |
| 상태 관리 | Zustand |
| 보드 렌더링 | HTML/CSS Grid |
| 체스 로직 | 자체 구현 (chess.js 미사용 — 변형 규칙 유연성 확보) |
| 온라인 대전 | Firebase Realtime Database |
| 배포 | Vercel |

## 기능 요구사항

### Phase 1 — 표준 체스

- 8×8 보드 렌더링 및 기물 초기 배치
- 클릭 또는 드래그로 기물 이동
- 기물별 이동 가능 범위 시각적으로 표시
- 이동 유효성 검사
  - 기본 이동 규칙 (폰, 룩, 나이트, 비숍, 퀸, 킹)
  - 특수 이동: 캐슬링, 앙파상, 폰 프로모션
  - 핀된 기물 이동 제한
- 체크 / 체크메이트 / 스테일메이트 판정
- 무승부 조건: 50수 규칙, 3회 반복 포지션
- 턴 관리 (백/흑 교대)
- 잡은 기물 스코어 표시
  - 플레이어별 패널에 잡은 기물 종류별 표시 (Q→R→B→N→P 순)
  - 기물 가치 기반 재료 우세 표시 (Q=9, R=5, B=3, N=3, P=1)
  - 잡은 기물 상세 팝업 (기물별 개수·점수, 형세 표시)
- 효과음 (이동, 캡처, 캐슬링, 체크, 프로모션, 게임 종료 각각 별도)
  - 게임 중 효과음 On/Off 토글 가능
- 현재 턴 식별 효과 (패널 애니메이션, 체크 뱃지, 보드 테두리 변화)
- 튜토리얼 모드
  - 12단계 순차 학습 (보드 소개 → 각 기물 이동 → 체크 → 체크메이트 → 특수 이동)
  - 기물 자동 선택 + 이동 가능 칸 표시, 단계별 설명

### Phase 2 — 규칙 시스템

- RuleSet 인터페이스로 체스 규칙을 교체 가능한 구조로 추상화
- 표준 규칙을 RuleSet 구현체로 분리
- 게임 시작 전 규칙 선택 UI 제공

### Phase 3 — 변형 규칙

| 이름 | 설명 |
|------|------|
| Chess960 | 기물 초기 배치를 랜덤으로 (백/흑 대칭, 비숍 이색, 킹이 룩 사이) |
| Crazyhouse | 잡은 기물을 자신의 기물로 보드에 놓을 수 있음 |
| Fog of War | 내 기물의 이동 범위 안에 있는 칸만 보임 |
| Atomic Chess | 기물을 잡으면 주변 기물도 함께 폭발 제거 |
| 킹 2개 | 두 킹을 모두 잡아야 승리 |
| 커스텀 기물 | 복합 능력을 가진 새로운 기물 (예: Amazon — 퀸+나이트 이동) |

### Phase 4 — 선택 기능

- AI 대전
  - Minimax + Alpha-Beta Pruning 알고리즘
  - 난이도 선택 (초급 / 중급 / 고급)
- 로컬 2인 대전 모드 선택
- 기보(이동 기록) 표시 및 되돌리기
- FEN 표기법으로 보드 상태 저장 및 불러오기

### Phase 5 — 게임 경험 향상

- **체스 시계 (타이머)**
  - 게임 시작 전 시간 모드 선택: 블리츠(3분/5분), 래피드(10분), 클래식(30분), 무제한
  - 각 플레이어별 남은 시간 카운트다운 표시
  - 시간 초과 시 해당 플레이어 패배 처리
  - 인크리먼트(이동 후 시간 추가) 옵션

- **기물 이동 애니메이션**
  - 기물 이동 시 출발지 → 목적지 슬라이딩 애니메이션
  - 캡처된 기물 사라지는 효과
  - 드래그 중에는 애니메이션 비활성화

- **힌트 기능**
  - 사이드 패널 "💡 힌트" 버튼으로 AI 추천 수 요청
  - 추천 출발지·목적지 칸 하이라이트 표시
  - 게임당 사용 횟수 제한 (기본 3회)
  - AI 대전 중에는 사용 불가

- **플레이어 이름 설정**
  - 게임 시작 전 두 플레이어 이름 입력 (미입력 시 "백"/"흑" 기본값)
  - PlayerPanel 및 게임 종료 화면에 이름 표시
  - AI 대전 시 흑 플레이어 이름은 "AI (난이도)" 자동 설정

- **전적 기록**
  - 플레이어 이름 기반으로 승/패/무 전적 localStorage 저장
  - 홈 화면에 최근 전적 요약 표시
  - 전적 초기화 기능

- **기보 리플레이**
  - 게임 종료 후 "다시보기" 버튼
  - 수 단위 앞/뒤 탐색 (← →) 및 처음/끝으로 이동
  - 자동 재생 (1초/수) 및 일시정지
  - 재생 중인 수를 기보 패널에서 하이라이트

### Phase 7 — 모바일 · 태블릿 대응

#### 현황 및 문제

| 항목 | 현재 값 | 문제 |
|------|---------|------|
| 보드 칸 크기 | 72px 고정 | 576px 고정 보드 → 모바일(360~430px)에서 화면 넘침 |
| 전체 레이아웃 | 보드 + 사이드 패널 가로 배치 | 최소 ~840px 필요, 세로 모드 모바일 불가 |
| 플레이어 패널·핸드 패널 | width: 576px 고정 | 모바일에서 가로 스크롤 발생 |
| 사이드 패널 | width: 240px 고정 | 모바일 레이아웃에서 공간 부족 |
| 터치 타겟 | 각종 버튼 소형 | 44px 미만 타겟은 터치 오조작 유발 |
| 홈·로비 화면 | 260px·320px 고정 폭 | 소형 화면에서 좌우 여백 부족 |

#### 반응형 보드 크기

- 보드 칸 크기를 CSS custom property `--sq`로 추상화
  - 계산 기준: `min(뷰포트 너비 - 여백, 뷰포트 높이 - 플레이어 패널·컨트롤 영역) / 8`
  - 최소 36px(손가락 한 칸 최소), 최대 80px(데스크톱)
- 보드·플레이어 패널·핸드 패널·드래그 고스트 등 72px 하드코딩 전체를 `var(--sq)` 기반으로 교체

#### 브레이크포인트 정의

| 이름 | 범위 | 레이아웃 방향 |
|------|------|--------------|
| mobile-s | ~ 480px | 세로 단일 컬럼, 보드 최대 크기 우선 |
| mobile | 481px ~ 700px | 세로 단일 컬럼 |
| tablet | 701px ~ 1000px | 세로 또는 가로 (방향에 따라 전환) |
| desktop | 1001px ~ | 현재 가로 배치 유지 |

#### 레이아웃 재구성 (mobile / tablet 세로)

- **보드 영역**: 화면 상단, `--sq` 기반으로 뷰포트에 맞게 축소
- **사이드 패널**: 보드 아래로 이동
  - 기보(MoveHistory): 고정 높이 스크롤 박스로 유지
  - 버튼 묶음(되돌리기·힌트): 가로 배치, 터치 타겟 48px 이상
  - FEN 박스: 기본 접힘, 토글로 펼치기
- **플레이어 패널**: 이름·타이머·잡은 기물을 한 줄에 압축 (모바일 compact 모드)

#### 터치 조작 개선

- 보드 영역에 `touch-action: none` 설정 → 드래그 중 페이지 스크롤 방지
- 드래그 감지 임계값(`DRAG_THRESHOLD`) 조정 검토 (터치는 마우스보다 떨림 큼)
- 힌트·프로모션 등 팝업 버튼 최소 크기 48×48px 보장
- 프로모션 선택 팝업: 화면 중앙 오버레이로 개선 (현재 보드 위 절대 위치는 소형 화면 시 잘릴 수 있음)

#### 홈 화면 / 온라인 로비

- 고정 폭(`260px`, `320px`) → `min(폭, 90vw)` 또는 `max-width` + `padding` 방식으로 전환
- 규칙 선택 카드: 소형 화면에서 2열 → 1열 자동 전환 (`flex-wrap` 이미 있으나 min-width 조정 필요)
- 방 코드 입력(`codeInput`): 소형 화면에서도 충분한 폰트 크기 유지

#### 기타 UI 처리

- 좌표 레이블(a–h, 1–8): 소형 화면에서 폰트 크기 축소
- 게임오버 다이얼로그: 화면 크기 대비 비율로 조정
- 튜토리얼 화면: 설명 텍스트 박스 모바일 레이아웃 대응
- `viewport` meta 태그: `width=device-width, initial-scale=1` 확인 (이미 Vite 기본 포함)

#### 미지원 유지 항목 (Phase 7 범위 외)

- Crazyhouse 핸드 패널 드래그(드롭)는 모바일 최적화 별도 검토
- PWA(홈 화면 추가, 오프라인 지원)는 Phase 8 이후 검토

### Phase 6 — 온라인 대전 · 배포

- **온라인 실시간 대전**
  - Firebase Realtime Database 기반 실시간 상태 동기화
  - 6자리 방 코드로 상대방 초대 (로그인 불필요, localStorage 익명 UID)
  - 방 만들기 (백 기물 고정) / 방 참가 (흑 기물 고정)
  - Crazyhouse를 제외한 모든 변형 규칙 온라인 지원
  - 온라인 대전 중 되돌리기·FEN 불러오기 비활성화
  - 프로모션은 퀸 자동 선택 (온라인 전용)
  - 상대 차례 대기 중 사이드 패널에 "상대 차례" 표시
  - 게임 종료 시 Firebase에 결과 기록, 양쪽 동시 반영

- **Vercel 배포**
  - Vite 빌드 결과물(`dist/`) Vercel에 자동 배포
  - SPA 라우팅을 위한 `vercel.json` 설정
  - Firebase 환경 변수를 Vercel 대시보드에서 관리

## 비기능 요구사항

- 모바일 브라우저에서도 터치로 기물 이동 가능
- 변형 규칙 추가 시 코어 로직 수정 없이 rules 디렉토리에만 파일 추가
- 기물 이미지: 오픈소스 라이선스 준수

## 개발 순서

```
Phase 1 (표준 체스) → Phase 2 (RuleSet 추상화) → Phase 3 (변형 규칙) → Phase 4 (선택 기능) → Phase 5 (게임 경험 향상) → Phase 6 (온라인 대전 · 배포)
```

Phase 1을 완전히 완성한 뒤 Phase 2 추상화를 진행하는 것을 원칙으로 한다.
